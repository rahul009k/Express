# 🟦 Nested Objects

---

## 📖 Definition

A **nested object** is an object that contains another object as a property value. This allows you to represent **complex, hierarchical data structures**.

```javascript
const company = {
    name: "OpenAI",
    location: {
        city: "San Francisco",
        country: "USA"
    }
};
```

---

## ❓ Why do we need Nested Objects?

Real-world data is often **hierarchical**. A company has a location, a location has a city and country. Nesting objects mirrors this structure naturally.

```javascript
// ❌ Without nesting
const companyName = "OpenAI";
const companyCity = "San Francisco";
const companyCountry = "USA";

// ✅ With nesting
const company = {
    name: "OpenAI",
    location: {
        city: "San Francisco",
        country: "USA"
    }
};
```

---

## 🔵 Accessing with Dot Notation

```javascript
console.log(company.name);
console.log(company.location.city);
console.log(company.location.country);
```

**Output**

```
OpenAI
San Francisco
USA
```

---

## 🟠 Accessing with Bracket Notation

```javascript
console.log(company["ceo"]["name"]);
```

**Output** → `Sam`

---

## 🔀 Mixed Notation

```javascript
console.log(company.ceo["age"]);
```

**Output** → `40`

---

## 💻 Full Example

```javascript
const company = {
    name: "OpenAI",
    location: {
        city: "San Francisco",
        country: "USA"
    },
    ceo: {
        name: "Sam",
        age: 40
    }
};

console.log(company.name);
console.log(company.location.city);
console.log(company.location.country);
console.log(company["ceo"]["name"]);
console.log(company.ceo["age"]);
console.log(company);
```

**Output**

```
OpenAI
San Francisco
USA
Sam
40
{ name: 'OpenAI', location: { city: 'San Francisco', country: 'USA' }, ceo: { name: 'Sam', age: 40 } }
```

---

## 🔄 Updating Nested Properties

```javascript
company.location.city = "New York";

console.log(company.location.city); // New York
```

---

## 🛡️ Optional Chaining ?.

Safely access nested properties without throwing an error.

```javascript
console.log(company?.founder?.name); // undefined — no error
```

Without optional chaining:

```javascript
console.log(company.founder.name); // ❌ TypeError
```

---

## ✅ Best Practices

✅ Use dot notation for known, fixed keys.

✅ Use optional chaining `?.` to safely access deep properties.

```javascript
console.log(company?.ceo?.name);
```

❌ Avoid nesting more than **3 levels** — it becomes hard to read.

---

## ⚠️ Common Mistakes

### ❌ Accessing a non-existent nested property

```javascript
console.log(company.founder.name); // ❌ TypeError
```

```javascript
console.log(company?.founder?.name); // ✅ undefined
```

---

## 🌍 Real-world Example

```javascript
const order = {
    id: 1001,
    customer: {
        name: "Rahul",
        email: "rahul@example.com"
    },
    product: {
        name: "Laptop",
        price: 75000
    },
    status: "shipped"
};

console.log(order.customer.name);  // Rahul
console.log(order.product.name);   // Laptop
console.log(order.product.price);  // 75000
console.log(order.status);         // shipped
```

## 💡 Interview Definition

> A nested object is an object that contains one or more objects as property values. Nested properties are accessed using **chained dot notation** or bracket notation. **Optional chaining** (`?.`) is used to safely access deeply nested properties without throwing an error if an intermediate property is `undefined`.
