# 🟦 JavaScript Modules

---

## 📖 Definition

A **Module** is a separate JavaScript file that contains code (functions, variables, classes) which can be **exported** and **imported** into other files.

Instead of writing everything in one file, we split code into multiple files — each file is a module.

---

## ❓ Why do we need Modules?

Without modules — one file with everything:

```javascript
// index.js — 1000 lines of code
// ├── Login
// ├── Register
// ├── Database
// ├── API
// ├── Math Functions
// ├── Validation
// ├── Email
// ├── Payments
// └── ...
```

❌ Hard to read, maintain, and debug.

With modules — split into separate files:

```
project/
│
├── index.js
├── math.js
├── user.js
└── calculator.js
```

✅ Clean, organized, and easy to manage.

---

## 📦 Two Types of Exports

| Type | Syntax | Import Syntax |
|:---:|:---:|:---:|
| Named Export | `export function name(){}` | `import { name } from "./file.js"` |
| Default Export | `export default name` | `import name from "./file.js"` |

---

## ✍️ Syntax

### Named Export
```javascript
// Exporting
export function add(a, b) {
    return a + b;
}

// Importing
import { add } from "./math.js";
```

### Default Export
```javascript
// Exporting
export default function add(a, b) {
    return a + b;
}

// Importing
import add from "./math.js";  // no curly braces
```

## 📊 Named Export vs Default Export

| Feature | Named Export | Default Export |
|:---|:---:|:---:|
| Curly braces on import | ✅ Required | ❌ Not needed |
| Multiple per file | ✅ Yes | ❌ Only one |
| Custom import name | ❌ Must match | ✅ Any name |
| Syntax | `export function` | `export default` |

---

## ✅ Best Practices

✅ Use **named exports** when a file exports multiple things.

```javascript
export function add() {}
export function subtract() {}
```

✅ Use **default export** when a file has one main thing to export.

```javascript
export default function multiply() {}
```

✅ Always use `./` for relative file paths.

```javascript
import { add } from "./math.js";  // ✅
import { add } from "math.js";    // ❌
```

✅ Include the `.js` extension in import paths for ES modules.

---

## ⚠️ Common Mistakes

### ❌ Wrong import syntax for named export

```javascript
import add from "./math.js";     // ❌ missing curly braces
import { add } from "./math.js"; // ✅
```

---

### ❌ Wrong import syntax for default export

```javascript
import { multiply } from "./calculator.js"; // ❌ no curly braces needed
import multiply from "./calculator.js";     // ✅
```

---

### ❌ Exporting a name that doesn't exist

```javascript
export { math };     // ❌ math is not defined
export { multiply }; // ✅ multiply is defined above
```

## 🌍 Real-world Example

```javascript
// auth.js
export function login(user) {
    console.log(user + " logged in");
}
export function logout(user) {
    console.log(user + " logged out");
}

// app.js
import { login, logout } from "./auth.js";

login("Arjun");
logout("Arjun");
```

**Output:**
```
Arjun logged in
Arjun logged out
```

## 💡 Interview Definition

> A **JavaScript Module** is a file that exports code (functions, variables, classes) so other files can import and use it. There are two types: **Named Exports** (use curly braces on import, multiple allowed per file) and **Default Exports** (no curly braces, only one per file). Modules help keep code **organized, reusable, and maintainable** by splitting large codebases into smaller focused files.
