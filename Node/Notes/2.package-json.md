# 2. package.json

## package.json field breakdown

### 1. `name`
- Example: `"name": "node-learning"`
- The project name.
- Must be unique when published to npm.
- Use lowercase and hyphens instead of spaces.
- Example names:
  - `expense-tracker-api`
  - `inventory-system`
  - `node-learning`

### 2. `version`
- Example: `"version": "1.0.0"`
- Uses Semantic Versioning: `MAJOR.MINOR.PATCH`
  - `1.0.1` → bug fix
  - `1.1.0` → new feature
  - `2.0.0` → breaking change

### 3. `description`
- Example: `"description": "Learning Node.js step by step"`
- A short project summary.

### 4. `main`
- Example: `"main": "index.js"`
- The entry point file for your package.
- When someone imports your package, Node uses this field to find the file.

### 5. `scripts`
- Example:
  ```json
  "scripts": {
    "start": "node index.js"
  }
  ```
- Scripts let you run commands with `npm start` instead of typing them manually.
- Very useful for Express and other Node projects.

### 6. `keywords`
- Example:
  ```json
  "keywords": ["node", "express", "api"]
  ```
- Helps when publishing the package to npm.

### 7. `author`
- Example: `"author": "Rahul"`
- The project owner's name.

### 8. `license`
- Example: `"license": "ISC"`
- Tells others how they can use your code.
- Common licenses: `ISC`, `MIT`, `Apache-2.0`, `GPL`.

### 9. `type`
- Example: `"type": "module"`
- Controls the module system used by Node.
- `commonjs` is the older system.
- `module` is the modern ES Modules system.
- Use `module` so you can write:
  ```js
  import fs from "fs";
  ```
  instead of:
  ```js
  const fs = require("fs");
  ```

## Notes
- `type: "module"` lets Node use ES Modules.
- `package.json` is the identity card for your Node project.
- `npm start` runs the start script defined in `scripts`.
- `node index.js` runs the file directly.
